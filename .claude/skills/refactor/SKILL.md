# 워크플로우

1. `git log --oneline -20`으로 최근 커밋 히스토리 파악
2. 변경된 파일들의 코드를 읽고 분석
3. 아래 기준으로 리팩토링 포인트 목록 작성
4. 사용자에게 리팩토링 목록을 보여주고 승인 받은 후 수정

# 분석 기준

| 항목               | 설명                                          |
| ------------------ | --------------------------------------------- |
| 중복 코드          | 동일/유사 로직이 여러 곳에 존재               |
| 공통 컴포넌트 분리 | 재사용 가능한 UI를 shared/ui로 추출           |
| 의존성 위반        | pages 간 직접 import, 역방향 의존             |
| 타입 개선          | any 사용, 불필요한 타입 단언, 누락된 타입     |
| 네이밍             | 폴더명 kebab-case, 컴포넌트명 PascalCase 위반 |
| 불필요한 코드      | 사용되지 않는 import, 변수, 함수              |
| 성능               | 불필요한 리렌더링, 최적화 가능한 쿼리         |

# 출력 형식

```
## 리팩토링 포인트

### [우선순위] 제목
- 파일: `경로`
- 문제: 설명
- 개선: 방안
```

# 규칙

- 실제 코드를 읽은 후에만 리팩토링 제안
- 동작 변경 없이 구조만 개선 (기능 유지)
- 사용자 승인 없이 코드 수정 금지
- .claude/rules/code-style.md 규칙 준수
