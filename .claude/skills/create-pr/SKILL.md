# 워크플로우

## 1단계: 변경사항 수집

```bash
git log main..HEAD --oneline
git diff main..HEAD --stat
git diff main..HEAD
```

## 2단계: 이슈 번호 추출

브랜치명에서 파싱:

- `1-feat/login-page` → #1
- `7-fix/auth-redirect` → #7

## 3단계: 변경 유형 분류

| 브랜치 접두사 | 유형        |
| ------------- | ----------- |
| `feat/`       | 기능 추가   |
| `fix/`        | 버그 수정   |
| `refactor/`   | 리팩토링    |
| `style/`      | 스타일 변경 |
| `chore/`      | 설정/빌드   |
| `docs/`       | 문서        |
| `test/`       | 테스트      |

## 4단계: PR 생성

먼저 `gh` CLI 사용 가능 여부 확인:

```bash
gh --version 2>/dev/null && echo "GH_AVAILABLE" || echo "GH_UNAVAILABLE"
```

### gh 사용 가능한 경우

브랜치 push 후 `gh pr create`로 생성:

```markdown
## ✨ 주요 변경사항

<!-- 변경 내용 요약 -->

---

## 📝 작업 상세 내용

<!-- 리뷰어가 특별히 봐줬으면 하는 부분 -->

---

## ✅ 체크리스트

- [ ] PR 본문에 `Close #번호` 추가
- [ ] 불필요한 주석, 디버깅 코드 제거
- [ ] 기능 테스트 및 정상 동작 확인
- [ ] 커밋컨벤션 / 코드컨벤션 준수

---

## 📸 스크린샷 (선택)

<!-- UI 변경 사항이 있다면 여기에 첨부해주세요 (Drag & Drop 가능) -->

---

## 🔍 기타 참고사항

<!-- 리뷰어에게 공유하고 싶은 추가 정보 -->

---

## 🔗 관련 이슈

- Close #<이슈번호>
```

### gh 사용 불가능한 경우

`gh pr create` 대신 PR 내용을 텍스트로 직접 출력:

1. PR 제목을 코드블록으로 출력
2. PR 본문(위 템플릿 채운 내용)을 코드블록으로 출력
3. "GitHub에서 직접 PR을 생성하고 아래 내용을 붙여넣으세요." 안내 메시지 출력

## 추가 모드 (--append)

`--append` 전달 시:

1. 마지막 push 이후 커밋만 분석
2. 기존 PR 본문의 작업 상세 내용에 추가

# 규칙

- 제목: 70자 이내
- 제목 형식: `[type]: 설명`
- 제목과 본문 항목은 명사형을 우선 사용함
- 기본 베이스 브랜치: `main`
- PR 생성 전 push 필수
- 브랜치명에서 이슈 번호 자동 추출
- 스크린샷 섹션은 사용자가 직접 추가
- Co-Authored-By, Generated by 등 AI 출처 표기 금지
