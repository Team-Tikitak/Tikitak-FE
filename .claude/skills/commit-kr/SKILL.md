# 기반

Udacity Git Commit Message Style Guide를 따릅니다.

# 워크플로우

1. `git status`와 `git diff --staged`로 변경사항 분석
2. `git log --oneline -10`으로 기존 커밋 패턴 참고
3. 아래 형식에 맞는 커밋 메시지 생성
4. **실행하지 않고** `git add`와 `git commit` 명령어를 출력

# 커밋 명령어 형식

```bash
git add <파일들>
git commit -m "<type>: <subject>"
```

HEREDOC, EOF, body(-m 두 번) 사용 금지. 제목 한 줄만.

# Type (Udacity Convention)

| Type       | 용도                                             |
| ---------- | ------------------------------------------------ |
| `feat`     | 새로운 기능                                      |
| `fix`      | 버그 수정                                        |
| `docs`     | 문서 변경                                        |
| `style`    | 코드 의미에 영향 없는 변경 (포맷팅, 세미콜론 등) |
| `refactor` | 버그 수정도 기능 추가도 아닌 코드 변경           |
| `test`     | 테스트 추가/수정                                 |
| `chore`    | 빌드 프로세스, 보조 도구, 라이브러리 변경        |

# 규칙

- subject: 한국어, 50자 이내, 마침표 없음
- subject는 명령형으로 작성 (ex: "로그인 폼 추가", "비밀번호 검증 로직 수정")
- scope 사용하지 않음. `type: subject` 형식만 사용
- 절대 직접 커밋하지 않음. 명령어만 출력
- 변경사항이 여러 기능/목적에 걸쳐 있으면 커밋을 잘게 쪼개서 각각 명령어 출력
- Co-Authored-By, Generated by 등 AI 출처 표기 금지
