# 알려진 이슈

우리 코드만으로 해결할 수 없는 외부 의존성, 브라우저/OS 정책, 네이티브 플랫폼 제약, 제공
자료 불일치는 여기에 기록합니다.

- 일시적인 로컬 환경 오류, 도구 sandbox 제약, 한 번의 빌드·명령 실패, 같은 변경에서
  해결 가능한 문제는 기록하지 않습니다.
- 우리 코드로 고칠 수 있지만 아직 안 한 일반 작업(기능 미구현, 리팩토링 백로그)은 여기가
  아니라 `.claude/tasks/todo.md`에 남깁니다. 기준은 "코드를 더 짜면 우리 힘으로 끝나는가,
  아니면 외부(OS/라이브러리/브라우저/제3자 정책)가 막고 있는가"입니다.
- 기록 전에는 재현 가능한 증상, 현재 사용자 또는 개발 흐름에 미치는 영향, 코드만으로
  해결할 수 없는 근거가 모두 있는지 확인합니다. 하나라도 없으면 `.claude/troubleshooting/`
  세션 기록이나 PR 설명으로만 남깁니다.
- 새 이슈는 `records/short-title.md`로 작성합니다.
- 증상, 영향, 원인 또는 근거, 임시 대응, 해소 조건을 기록합니다.
- 구현으로 해결한 이슈는 삭제하지 않고 해결 상태와 해결일을 갱신합니다.
- 비슷한 이슈가 다시 발생하면 새 문서를 만들기 전에 기존 기록의 조건과 대응을 먼저
  확인합니다.
- 상태는 `open`, `monitoring`, `resolved`, `wontfix` 중 하나로 기록합니다. 외부 조치가
  필요한 경우 담당 주체와 다음 확인 시점을 남깁니다.
- 재현 절차와 관찰 근거가 없는 추측성 메모는 기록하지 않습니다.
